# 2026-09-15

## Fixed the 3 core skills Antigravity couldn't parse

Antigravity logged `skills.go:199] Failed to parse skill file …` on every startup for
`verify-this`, `md-slides`, `mcpm-manager`. Root causes were two different bugs:

1. **`verify-this` + `mcpm-manager`** — unquoted `description` containing `": "`
   ("return exactly one verdict: VERIFIED" at col 162; "NOT for: writing" at col 255).
   Fixed by emitting the value as a YAML single-quoted scalar (`'` doubled). Round-trip
   asserted against pyyaml before writing.

2. **`md-slides`** — NOT a truncation issue. Its description contained the literal
   `` `---` ``. Any frontmatter extractor that does `content.split("---")[1]` cuts the
   block open at that inline `---`, leaving an unterminated `"` → go-yaml
   "found unexpected end of stream". Fixed by rewording to
   "horizontal-rule (HR) boundaries". This is why only 1 of 152 skills hit it.

**Reusable diagnostic**: scan every `*/SKILL.md` twice — once with
`re.match(r"^---\n(.*?)\n---\n", txt, re.S)` + `yaml.safe_load`, and once with
`yaml.safe_load(txt.split("---")[1])`. The second model catches the inline-`---` class
that the first one misses entirely.

After the fix: strict frontmatter failures 152 → **0**.

Also found and then fixed on request: `plan-first` had no `name`/`description` in its
frontmatter at all (only `triggers` + `not_for`), so agents could not match it. Added
both; `name: plan-first` matches the directory, and the 498-char description covers the
three-stage workflow plus the Chinese trigger phrases. When authoring a description by
hand, avoid `": "` entirely (some harnesses do `line.split(": ", 1)`) and quote it anyway.

Final state of the core set (152 skills): strict frontmatter failures **0**, naive
`split("---")` failures **0**, missing `name`/`description` **0**.

Backups of the originals: `/tmp/skill-backup/{verify-this,md-slides,mcpm-manager}.SKILL.md`.

### The DMG corruption reproduced, and is now fully diagnosed
`npm run package:mac -- --config.mac.notarize=false` exited 0 and produced a dmg that
`hdiutil verify` called VALID — but mounting it showed `Contents/Info.plist` **gone**,
replaced by a 3740-byte `.BC.T_zC7n4J`, plus a `.BC.T_8wVczg` where `PkgInfo` was. The
sandbox log listed 165 denied `file-write-unlink` operations, all under
`/Volumes/SkillsGate 0.6.2-arm64/...`: the sandbox renames each file it touches to a
`.BC.T_*` backup and then cannot unlink it, so the backups strand inside the mounted image.

**`hdiutil verify` only checksums the filesystem, not the bundle** — it is not a usable gate.

Fix that works: `release/mac-arm64/SkillsGate.app` is untouched (corruption is confined to
the mounted volume), so `hdiutil create -srcfolder release/mac-arm64 … -format UDZO` from
it yields a clean image (needs sandbox bypass). Then patch the dmg `sha512`/`size` in
`latest-mac.yml` and regenerate the blockmap with
`node_modules/app-builder-bin/mac/app-builder_arm64 blockmap` (note: `app-builder_arm64`,
not `app-builder`).

Final: dmg 121,333,036 B, sha512 matches `latest-mac.yml`, 0 `.BC.T_*` anywhere,
`codesign --verify --deep --strict` passes (ad-hoc), `app.asar` carries the split.
The `.zip` target is built from the app dir and was clean all along.

All of the above is now written up in `AGENTS.md` under "Packaging a macOS release
(DMG + zip)". Committed as `f7c26b9`.
